# 三種 Agent 類型比較

## 開始之前：你真的需要 AI Agent 嗎？

不是所有問題都需要 AI 來解決。以下情境用傳統程式就能處理，不需要 Agent：

- **規則完全固定且可窮舉**：例如「訂單金額 > 1000 就打九折」，用 if-else 比 AI 便宜一百倍
- **不需要理解自然語言**：用戶只是點按鈕、選選單，不需要 AI 理解文字
- **輸出格式完全固定**：例如「查詢後回傳 JSON」，不需要 AI 組織語言
- **零容錯**：如果答錯一次就會造成嚴重後果（例如醫療診斷、法律判決），目前的 AI 還不夠可靠

**什麼時候才需要 Agent？**

- 用戶會用自然語言提問，而且問法不固定
- 需要根據上下文做判斷，不是簡單的規則對應
- 輸出需要組織語言，不是固定模板
- 可以接受偶爾出錯，有人工兜底機制

## AI 可行性快速判斷

決定要做 Agent 之前，先用這三個問題快速評估可行性：

1. **有沒有明確的「對」和「錯」？**
   - 有明確標準（例如查訂單狀態）→ 可行性高
   - 標準模糊或主觀（例如「判斷文章寫得好不好」）→ 可行但品質不穩定
   - 完全沒有標準（例如「預測股價」）→ 不建議

2. **出錯的代價有多大？**
   - 錯了沒關係（例如推薦商品）→ 適合 AI
   - 錯了有點麻煩但可補救（例如客服回答錯誤，可轉人工）→ 適合，但要加 fallback
   - 錯了代價很大（例如自動執行交易）→ 不建議全自動，AI 只做建議，人做決定

3. **有沒有足夠的參考資料？**
   - 有完整的 FAQ / 知識庫 / 資料庫 → 可行性高
   - 資料零散或不完整 → 可行但需要先整理資料
   - 完全沒有 → 先建資料，再做 Agent

## 總覽

| | 簡單型 | 分流型 | 自主型 |
|---|---|---|---|
| **一句話說明** | 一個任務、一條路 | 先判斷意圖、再走對應路線 | AI 自己決定怎麼做 |
| **典型場景** | 翻譯、摘要、固定格式回覆 | 客服分流、多功能助手 | 自動分析報告、產出簡報 |
| **流程控制** | 固定流程，不需判斷 | 管線式，設計者預先規劃路線 | AI 動態決定工具和步驟 |
| **需要意圖分析** | 不需要 | 需要（路由器） | 不需要（模型自己判斷） |
| **適合的模型** | 低階模型即可 | 低階模型 + 意圖分析 | 需要高階模型 |
| **成本** | 低 | 中等 | 較高 |
| **複雜度** | 低 | 中 | 高 |

## 怎麼判斷你需要哪一種？

**問自己三個問題：**

1. **你的 Agent 要處理幾種任務？**
   - 只有一種 → 簡單型
   - 兩三種，可以事先列出來 → 分流型
   - 很多種，或無法事先列舉 → 自主型

2. **流程能不能事先規劃？**
   - 每次都走一樣的步驟 → 簡單型
   - 根據意圖走不同路線，但路線是固定的 → 分流型
   - 每次不一樣，要看情況決定 → 自主型

3. **你對成本敏感嗎？**
   - 很敏感，能省則省 → 簡單型或分流型
   - 品質優先，成本其次 → 自主型

## 決策評分表

如果三個問題還是讓你猶豫不決，用這個評分表量化判斷：

| 維度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 任務種類數 | 只有 1 種 | 3-5 種 | 10 種以上或無法列舉 |
| 流程可預測性 | 每次完全一樣 | 大致固定，偶爾例外 | 每次都不一樣 |
| 需要的判斷能力 | 不需判斷 | 簡單分類 | 複雜推理 |
| 錯誤容忍度 | 不容許出錯 | 偶爾出錯可接受 | 可自動修正 |
| 預算敏感度 | 越便宜越好 | 有一定預算 | 品質優先 |

**加總結果：**
- **5-10 分** → 簡單型
- **11-18 分** → 分流型
- **19-25 分** → 自主型

## 先簡單再進化——迭代策略

不要一開始就做最複雜的架構。建議的進化路線：

**第一步：用簡單型驗證核心價值**

先用最簡單的架構把核心功能上線。例如：先做一個固定流程的 FAQ 機器人，驗證用戶確實會用、確實有幫助。

**第二步：根據數據決定要不要升級**

上線後觀察：用戶的問題是否超出固定流程的範圍？是否有多種意圖需要分流？如果是，再升級到分流型。

**第三步：只在必要時用自主型**

只有當任務範圍廣、步驟無法預測、且你願意承擔較高成本時，才考慮自主型。

**原則：能用簡單型解決就不要用分流型，能用分流型就不要用自主型。**

## 混合架構

實務上，很多 Agent 不是純粹的某一種類型，而是混合使用：

- **分流型 + 簡單型子任務**：路由器判斷意圖後，每條路線走各自的固定流程。這是最常見的組合。
- **分流型入口 + 自主型複雜路線**：大部分意圖用簡單流程處理，少數複雜意圖交給自主型子 Agent。
- **自主型 + 簡單型工具**：自主型 Agent 的每個工具內部，其實就是一個簡單型的固定流程。

混合架構的好處是：簡單的任務用低成本處理，只在真正需要的地方投入高成本的自主決策。
