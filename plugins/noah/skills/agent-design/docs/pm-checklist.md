## Agent 需求規格模板

設計完架構後，用這個模板整理需求，交給工程師開發：

### 基本資訊

- **Agent 名稱**：
- **一句話描述**：這個 Agent 要幫用戶做什麼？
- **架構類型**：簡單型 / 分流型 / 自主型
- **目標用戶**：誰會用這個 Agent？

### 任務定義

- **核心任務**：列出 Agent 要處理的所有任務
- **每個任務的輸入**：用戶會提供什麼資訊？
- **每個任務的輸出**：Agent 應該回什麼？格式？
- **超出範圍的處理**：用戶問了不該問的，怎麼回應？

### 資料來源

- **需要查詢的資料庫**：列出資料表和欄位
- **需要搜尋的知識庫**：FAQ、產品說明、政策文件等
- **資料更新頻率**：即時 / 每日 / 每週

### 行為規範

- **一定要做的事（Dos）**：例如查無結果時引導聯繫客服
- **一定不能做的事（Don'ts）**：例如不能透露內部價格策略
- **語氣風格**：正式 / 親切 / 專業
- **回應長度**：簡短 / 中等 / 詳細

### 記憶需求

- **需要記住前幾輪對話**：5 輪 / 10 輪 / 全部
- **需要跨對話記住用戶偏好嗎**：是 / 否
- **需要記住用戶的操作歷史嗎**：是 / 否

## System Prompt 資訊清單

PM 不需要自己寫 System Prompt，但需要提供以下資訊給工程師：

| 項目 | 你要回答的問題 | 範例 |
|------|----------------|------|
| **角色** | 這個 AI 是誰？ | 「你是 XX 公司的客服助手」 |
| **職責** | 它的主要工作是什麼？ | 「回答用戶關於訂單和退貨的問題」 |
| **能做的事** | 有哪些是它該做的？ | 「查詢訂單狀態、解釋退貨政策、轉接人工客服」 |
| **不能做的事** | 有哪些是絕對禁止的？ | 「不能承諾退款金額、不能透露內部折扣規則」 |
| **語氣** | 用什麼口吻說話？ | 「親切但專業，像有經驗的客服人員」 |
| **查無資料** | 找不到答案時怎麼辦？ | 「告訴用戶無法查到，建議撥打客服電話」 |
| **不確定** | AI 不確定時怎麼辦？ | 「說明不確定，不要猜測，引導用戶提供更多資訊」 |
| **回應格式** | 有沒有特定的格式要求？ | 「先回答問題，再列出相關連結」 |

## 成本估算參考

### 各類型的 Token 消耗量級

| | 簡單型 | 分流型 | 自主型 |
|---|---|---|---|
| **每次對話的 Token 量** | 1K - 3K | 3K - 10K | 10K - 100K+ |
| **API 呼叫次數** | 1 次 | 2-3 次 | 5-50+ 次 |
| **適合的模型** | Haiku | Haiku + Sonnet | Sonnet / Opus |

> Token 是什麼？可以理解為「AI 處理的文字量」。大約 1 個中文字 ≈ 1-2 個 token。

### 模型選擇建議

| 模型等級 | 代表 | 每百萬 token 成本（概略） | 適合場景 |
|----------|------|--------------------------|----------|
| **輕量** | Claude Haiku | ~$0.25 - $1 | 意圖分類、簡單問答、格式轉換 |
| **中階** | Claude Sonnet | ~$3 - $15 | 複雜問答、內容生成、多步推理 |
| **高階** | Claude Opus | ~$15 - $75 | 困難推理、程式碼生成、自主決策 |

> 以上為概略參考，實際價格請查閱各供應商最新定價。

### 月成本粗估公式

```
月成本 ≈ 日活用戶數 × 每人每日對話次數 × 每次對話 token 數 × 每 token 單價
```

**範例：簡單型客服機器人**
- 1,000 日活 × 3 次/天 × 2,000 tokens × $0.5/百萬 ≈ **$3/月**

**範例：分流型多功能助手**
- 500 日活 × 5 次/天 × 6,000 tokens × $5/百萬 ≈ **$75/月**

**範例：自主型分析助手**
- 100 日活 × 2 次/天 × 50,000 tokens × $10/百萬 ≈ **$100/月**

## 上線前檢查清單

### 測試

- [ ] 準備 50+ 個測試案例（golden set），涵蓋正常和邊界情境
- [ ] 每個測試案例有預期的正確回答，可以自動比對
- [ ] 測試「查無結果」的情境——AI 是否正確引導用戶
- [ ] 測試「超出範圍」的問題——AI 是否拒絕回答
- [ ] 測試惡意輸入——AI 是否會洩露系統資訊或被操控

### Guardrails（防護欄）

- [ ] 輸入過濾：偵測並阻擋明顯的惡意輸入（prompt injection）
- [ ] 輸出檢查：確認 AI 回應不包含敏感資訊、不違反行為規範
- [ ] 幻覺偵測：當 AI 的回答無法對應到檢索結果時，標記為「不確定」
- [ ] Fallback 機制：AI 無法處理時，自動轉接人工

### 監控指標

- [ ] 回答準確率（抽樣人工評分）
- [ ] 用戶滿意度（對話結束後的評分）
- [ ] Fallback 比例（轉人工的頻率）
- [ ] 平均每次對話成本
- [ ] 回應延遲時間
